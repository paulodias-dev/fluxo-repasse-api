# Fechamento mobile
Solicitação de exclusão autenticada, idempotente e cancelável; nenhum apagamento automático ou desativação. Preservar último administrador, dados de outros participantes, histórico financeiro e retenção legal. Operador deve tratar fila account_deletion_requests (status pending) sob política de privacidade aprovada e canal de atendimento, verificar titularidade, transferência de responsabilidade, retenção e revogação; não declarar exclusão concluída. Não há fluxo final de anonimização/eliminação, nem prazo inventado. Revogação Apple CLI exige solicitação pendente e --confirm, não apaga dados; use somente após revisão e evitar login concorrente durante tratamento. Exchange opcional por APPLE_NATIVE_EXCHANGE_REQUIRED=true e Team ID/Key ID/P8 reais, nunca versionar. A nova autorização obtém refresh token cifrado e correlaciona subject. Contas anteriores precisam reautorizar; não afirmar revogação se sem token. Para submissão à loja, finalizar política de exclusão, validar revogação e publicar canal de exclusão web exigido pelo Google. BI: coorte de vendidos pela data de venda; resultado = venda + receita adicional realizada - compra - despesa realizada; custos históricos da coorte, não caixa no período. Giro somente compras datadas válidas; média resultado somente valores conhecidos; tipos de veículo em vez de segmentos de mercado; repasses aprovados não cancelados com parcelas não estornadas, permissão repasse.manage, não misturar relatos externos. Testes feature escritos, não executados. API e web existentes preservadas; migration aditiva, sem deploy automático.
